## 2. 代码与页面实现

### 2.1 真实工作台统计

新增 `GET /stats/tickets`，返回：

```json
{
  "total": 0,
  "aiProcessing": 0,
  "manualReview": 0,
  "resolved": 0,
  "closed": 0,
  "slaWarning": 0,
  "slaEscalated": 0,
  "categoryCounts": {
    "REFUND": 0,
    "LOGISTICS": 0,
    "DAMAGE": 0,
    "INVOICE": 0,
    "OTHER": 0
  }
}
```

统计范围严格复用角色约定：

- `USER`：仅统计自己的工单。
- `AGENT`：统计自己已接取的工单，以及尚未分配的人工复核工单。
- `ADMIN`：统计全部未删除工单。

前端工作台显示总数、AI 处理中、待人工、已解决/已关闭、分类占比和 SLA 风险，不再显示静态占位数字。

### 2.2 管理员用户/客服列表

新增 `/home/users` 路由和管理员菜单，调用正式的
`GET /users?current=&size=&role=`：

- 支持分页。
- 支持 USER、AGENT、ADMIN 角色筛选。
- 只展示基础资料，不展示密码、Token 等敏感信息。
- 前端路由限制为 ADMIN，后端继续以 `user:manage` 权限作为最终安全边界。

### 2.3 管理员分配和改派

管理员在 `MANUAL_REVIEW` 工单详情中可加载客服列表并选择处理人，调用
`PUT /tickets/{id}/assignee`。后端继续验证目标账号必须是有效 AGENT，并写入分配或改派日志。

根据第 2.2 节责任边界，管理员不再通过普通消息接口直接参与对话；管理员处理工单时使用分配、解决、关闭等可审计专用动作。

### 2.5 模型配置说明

确认正式后端通过 Spring AI Alibaba Agent Framework `1.1.2.0` 和 DashScope
Starter `1.1.2.2` 接入 DashScope，默认使用 `qwen3.7-max`，温度为
`0.7`。模型用于普通/SSE 对话、工单分类、工单回复和受控只读 Tool Calling。

模型名和温度已改为可由本机环境变量覆盖：

```properties
spring.ai.dashscope.chat.options.model=${DASHSCOPE_MODEL:qwen3.7-max}
spring.ai.dashscope.chat.options.temperature=${DASHSCOPE_TEMPERATURE:0.7}
```

启动和模型切换说明已同步到根目录及后端 README；真实 Key 仍只通过
`DASHSCOPE_API_KEY` 注入，不进入源码和 Git。

### 2.6 SSE 真实联调问题修复

2026-07-29 在本地真实 DashScope 环境复现“AI 客服一直正在思考”：

- 同一账号调用普通 `POST /ai/chat` 约 1 秒正常返回，证明数据库、Key、模型和同步 ChatClient 可用。
- 旧 `POST /ai/chat/stream` 能返回 `200 text/event-stream`，但约 1 秒后在没有任何事件帧的情况下关闭；页面因缺少等待上限而一直保留加载状态。
- 将 DashScope Starter 从 `1.1.2.0` 升级至 `1.1.2.2`，流式控制器使用 Spring MVC 原生 `ServerSentEvent` 输出 `message`、`done`、`error` 事件并统一为 UTF-8，避免协议文本被二次编码到正文。
- 后端增加 60 秒模型超时、完整异常日志和完成日志；前端增加 70 秒取消与可见超时提示。
- SSE 结束后的 Servlet `ASYNC` 二次派发跳过重复 Sa-Token 鉴权，避免访问已释放的 ThreadLocal 上下文并产生 `SaTokenContext 尚未初始化`。
- 新增 5 项控制器/配置测试，覆盖 SSE 事件结构、HTTP 单次编码、异常帧、UTF-8 和异步鉴权。代码修复后仍须重启 IDEA 后端，再进行真实页面复测。
