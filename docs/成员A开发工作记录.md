## 4. 实现清单

### 4.1 账号与认证

- 新增 `POST /user/register`、`GET /user/profile`、`PUT /user/profile`。
- `POST /user/logout` 作为唯一正式退出接口；移除 GET 修改登录状态，避免退出被预取或缓存请求意外触发。
- 登录响应增加正式字段 `id`、`role`，同时保留 `userId`、`roles` 供现有前端过渡。
- 注册角色强制为 `USER`，个人资料接口不允许修改用户名、角色和信誉分。
- 删除/禁用用户不再能参与登录、角色或权限计算。

### 4.2 响应、异常与安全

- 统一业务异常的 HTTP 状态和响应业务码；补齐 400、401、403、404、409、500。
- Bean Validation 字段错误固定返回在 `data.fieldErrors`。
- 重复用户名在业务检查和数据库唯一索引并发冲突两层均返回 409。
- 移除创建工单时输出完整请求对象的调试日志，避免业务内容进入控制台。

### 4.3 角色与数据范围

- `USER`：本人订单/工单、创建工单、补充消息。
- `AGENT`：已分配给自己、属于本组，或未绑定任何坐席组的公共池人工工单；不可读取用户订单。
- `ADMIN`：全量订单、用户和管理权限。
- 未知角色在工单分页 SQL 中默认返回空数据，避免因配置错误获得全量数据。
- 普通用户访问他人订单或使用他人订单创建工单均返回 403。

### 4.4 契约兼容

- 创建工单正式字段统一为 `orderId`，后端用 `@JsonAlias` 暂时兼容 `ordersId`。
- 发送工单消息的请求体只保留 `content`，工单 ID 只从路径获取。
- 新增正式订单分页 `GET /orders?current=1&size=10`，暂时保留旧路径分页供 7-28 前端迁移。
