# 丰富演示数据说明

## 1. 用途

`ticketsystem/src/main/resources/static/seed_rich_demo_data.sql` 用于在已经初始化、已经迁移的 `ticket_system` 数据库上追加联调和展示数据。适合验证：

- 用户、订单和工单长列表分页；
- 工单状态、分类、优先级、SLA 和归档筛选；
- 四个坐席组的数据范围、接单和组长报表；
- 工单消息、操作日志、AI 处理历史和满意度；
- FAQ、售后策略、动态分类和 AI 会话恢复。

脚本不是全量初始化脚本，不会删除或重建已有业务表。

## 2. 执行方法

先确认已经执行：

1. `ticket_system.sql`
2. `data.sql`（全新库需要）
3. `migrate_full_requirements.sql`

在仓库根目录使用 UTF-8 客户端：

```powershell
mysql --default-character-set=utf8mb4 -u root -p
```

进入 MySQL 后执行：

```sql
source ticketsystem/src/main/resources/static/seed_rich_demo_data.sql;
```

不要只依赖 `SET NAMES utf8mb4` 修复 Windows 文件读取编码；应在启动 `mysql` 客户端时指定 `--default-character-set=utf8mb4`。

## 7. 幂等和安全说明

- 不包含 `DROP TABLE`、`TRUNCATE` 或业务数据删除语句。
- 用户、订单、工单和会话使用唯一业务编号判断是否已存在。
- 消息、日志、满意度、FAQ 和策略使用所属工单及内容/动作判断是否已写入。
- 所有正式写入位于同一事务中，出现 SQL 异常时执行 `ROLLBACK` 并重新抛出错误。
- 脚本开始时检查最新迁移所需的表和字段；未执行迁移时主动终止。

验证时使用隔离的 MySQL 8.0.42，连续执行脚本两次，第二次执行后的用户、订单、工单、消息、日志和会话数量均未增长。

## 8. 快速核对

```sql
SELECT COUNT(*) FROM sys_user WHERE username LIKE 'demo_2026_%';
SELECT COUNT(*) FROM orders WHERE order_no LIKE 'DEMO2026%';
SELECT status, COUNT(*) FROM ticket
WHERE ticket_no LIKE 'DEMO-TK-%'
GROUP BY status;
SELECT category, COUNT(*) FROM ticket
WHERE ticket_no LIKE 'DEMO-TK-%'
GROUP BY category;
```

脚本执行结束时也会直接输出各类演示数据的实际数量。
