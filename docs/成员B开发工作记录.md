## 2. 整合时修正的问题

筛选不是机械复制；以下内容已按 A/C 正式接口修正：

1. B 原注册页假设注册响应包含 Token 并自动登录，但 A 的正式接口返回用户资料。现改为注册成功后跳转登录页并带入用户名。
2. 订单分页由旧 `/orders/{page}/{pageSize}` 改为 `/orders?current=&size=`，详情由旧 `/orders/detail/{id}` 改为 `/orders/{id}`。
3. 创建工单字段由旧 `ordersId` 改为正式 `orderId`；仍兼容读取旧查询参数，但提交只发送正式字段。
4. 删除 B 前端通用 `PUT /tickets/{id}`，保留 C 的接单、分配、解决、关闭、转人工专用接口。
5. 角色菜单与后端权限对齐：AGENT 不显示订单入口；只有 USER 显示创建工单；ADMIN 显示全量订单和策略。
6. 请求层增加 409 并发冲突和 503 服务不可用提示，并使用后端 `msg`。
7. C 的工单详情接入 B 的 `MessageBubble`，不覆盖 C 的状态动作和权限判断。
