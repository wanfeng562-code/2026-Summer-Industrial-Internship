# 缺陷修复与逻辑漏洞审计记录

## 1. 文档目的

本文集中记录项目接手以来在启动、数据库、认证权限、工单状态机、AI/SSE、前后端契约和配置管理中发现的缺陷。记录内容区分：

- **已修复并自动化验证**：代码已经修改，相关测试或生产构建通过。
- **已修复，待真实环境验收**：静态检查、单元测试或构建通过，但仍需 MySQL、浏览器或真实 DashScope 验证。
- **验收风险**：当前没有证据表明代码错误，但无法用离线测试替代真实环境确认。

AI 不直接获得数据库连接或任意 SQL 权限。所有业务数据查询都必须经过后端只读服务、当前登录身份和数据归属校验。

## 2. 对话过程中已经完成的缺陷修复

| 类别 | 缺陷表现 | 根因 | 修复方式 | 状态 |
| --- | --- | --- | --- | --- |
| 数据库初始化 | `data.sql` 中文乱码、字段长度异常 | Windows `mysql source` 使用的客户端字符集与脚本不一致，旧库字段也可能未按最新 DDL 创建 | README 统一使用 `mysql --default-character-set=utf8mb4`；要求先执行结构脚本，再执行数据脚本 | 已修复说明，需真实库复验 |
| MySQL 兼容 | `ADD COLUMN IF NOT EXISTS` 在 MySQL 8.0.42 报 1064 | MySQL 的 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 兼容性假设错误 | 改为查询 `information_schema` 的可重复执行存储过程；迁移脚本使用 ASCII，避免客户端误解中文 | 已修复，脚本静态检查通过 |
| 配置安全 | 数据库和 DashScope 无法启动或密钥容易误提交 | 环境变量配置入口不清晰 | 使用 `DB_PASSWORD`、`DASHSCOPE_API_KEY` 和可选 `DASHSCOPE_MODEL`；README 补充 IDEA 配置路径 | 已修复说明 |
| 认证与越权 | 普通用户可能读取他人订单/工单，页面隐藏按钮不能形成真实授权 | 老师快照偏重演示，服务层归属校验不完整 | 订单、工单、消息、日志、AI 上下文均在服务层按 Token 用户再次校验；统一 401/403 | 已修复并测试 |
| 状态机 | 通用更新路径可能绕过接单、解决、关闭流程 | 状态修改没有收敛到专用业务动作 | 移除任意状态写入，改为接单、分配、解决、关闭、驳回、跟进、归档等专用接口和原子状态更新 | 已修复并测试 |
| 密码安全 | 演示明文密码可能继续留在数据库 | 旧数据与新认证实现不一致 | 登录时兼容旧明文并立即升级 BCrypt；新注册和密码重置只存 BCrypt | 已修复并测试 |
| SSE 协议 | 前端正文出现 `event:message`、`data:` 和 `[DONE]` | 后端/前端重复封装 SSE，换行与 UTF-8 处理不一致 | 后端使用原生 `ServerSentEvent`；前端按完整帧解析 `session/message/done/error` | 已修复并测试 |
| SSE 异步鉴权 | 响应提交后出现 `Cannot render error page` | SSE 完成后的 Servlet `ASYNC` 二次派发再次进入 Sa-Token，并访问已释放上下文 | 初次 `REQUEST` 正常鉴权，`ASYNC` 二次派发不重复校验 | 已修复并测试 |
| AI 卡住 | 页面长期显示“正在思考”，后端缺少可定位日志 | 模型调用没有明确超时、取消和可见异常 | 后端 60 秒超时，前端 70 秒取消；增加 AI 请求、完成、失败日志和停止生成按钮 | 已修复，真实模型已完成基础验证 |
| AI 业务查询 | 不能列出本人全部订单/工单；`TK...` 被当成数字 ID；流式工具误报登录异常 | 工具只有精确查询，参数类型错误；流式线程再次读取 Sa-Token ThreadLocal | 增加本人列表工具；兼容订单号、工单号和数字 ID；后端通过 `ToolContext` 传递可信用户 ID | 已修复并通过自动化测试，待真实 Tool Calling 复验 |
| AI 会话连续性 | 切换页面后回到初始问候，模型也不记得上文 | 前端只加载会话列表；后端每次只把当前一句交给模型 | 前端恢复浏览器记住或最近会话；模型携带最近 12 条已鉴权历史消息 | 已修复并通过前端构建 |

## 3. 2026-07-29 全项目追加审计

本轮按以下范围检查：

1. 控制器是否有登录、权限、参数上限和正确 HTTP 语义。
2. 服务层是否再次执行角色、数据归属、软删除和状态校验。
3. 工单是否存在跳级、逆向、归档后写入或跨坐席组操作。
4. 动态分类、坐席组、FAQ、策略之间的引用是否可能失效。
5. CSV 导入导出是否可能部分写入、返回假成功、触发 Excel 公式。
6. AI Tool Calling 是否可能丢失身份、越权或直接写业务数据。
7. 前端路由、按钮、接口类型、401 处理和持久化状态是否与后端一致。

### 3.1 已确认缺陷与处理结果

| 编号 | 模块 | 确认缺陷 | 修复结果 |
| --- | --- | --- | --- |
| AUD-01 | 工单归档 | 已归档的驳回工单仍可发送消息、跟进重开或调整优先级 | 已修复：服务层和页面同时禁止归档后写入；优先级 SQL 也增加 `archived=0` 原子条件 |
| AUD-02 | 工单分组 | 分类默认组会在建单时直接把组长写入 `agentId`，绕过接单/管理员分配约定 | 已修复：建单只写 `groupId`，`agentId` 仅由接单或管理员分配写入 |
| AUD-03 | 工单分配 | 管理员可把有负责组的工单分配给其他组客服 | 已修复：后端拒绝跨组分配，前端候选客服也按负责组过滤 |
| AUD-04 | 动态分类 | 启用分类可绑定停用组；分类编码可被 API 改名，导致历史引用断裂 | 已修复：启用分类只能绑定启用组；创建后编码不可修改 |
| AUD-05 | 坐席组 | 删除被分类或工单引用的组会留下失效引用；成员可被静默移入另一组 | 已修复：存在引用时禁止删除；跨组成员调整要求先从原组移除 |
| AUD-06 | 工作台 | 分类统计只包含五个内置编码，新增动态分类被遗漏 | 已修复：保留内置零值并合并数据库中出现的动态分类 |
| AUD-07 | FAQ CSV | 非法 `enabled` 抛 500，空文件等错误以 HTTP 200 包装业务 400 | 已修复：统一返回 400，并附记录起始行 |
| AUD-08 | CSV 安全 | 工单标题或 FAQ 以 `= + - @` 开头时，Excel 打开 CSV 可能执行公式 | 已修复：统一 CSV 单元格转义并中和公式前缀 |
| AUD-09 | FAQ 语义检索 | 分类未校验；模型重复或乱序评分会直接进入结果 | 已修复：校验启用分类；结果按 FAQ ID 去重、分值降序和阈值截断 |
| AUD-10 | SSE 登录失效 | 流式接口返回 401 时 Axios 拦截器不会运行，前端仍保留过期 Token | 已修复：Fetch SSE 独立解析错误体，401 清理登录态并跳转登录 |
| AUD-11 | 旧分页接口 | 兼容订单分页路径没有页码、页大小校验，可绕过新版接口的 100 条上限 | 已修复：旧接口同样限制页码至少 1、页大小最多 100 |
| AUD-12 | 异常映射 | DTO 出现对象级校验错误时强制转换 `FieldError` 可能再次抛异常 | 已修复：对象级错误使用 `_global` 键，不再强制转换 |
| AUD-13 | 坐席数据范围 | 详情、列表、工作台和 AI 查询把任何未接人工工单当作公共池，可能泄露其他组工单 | 已修复：四条链路统一为同组可见；只有 `groupId` 和 `agentId` 都为空的人工工单属于公共池 |
| AUD-14 | 账号状态 | 已软删除账号使用正确密码仍可获得 Token | 已修复：登录前校验 `deleted`，返回统一 401 且不创建会话 |
| AUD-15 | FAQ 导入 | 导出内容含多行答案时无法再导入；CSV 导入绕过 DTO 校验并可能部分写入非法数据 | 已修复：按完整 CSV 记录读取多行字段；服务层执行 Bean Validation；整批事务回滚 |
| AUD-16 | 输入与资源边界 | 查询筛选、AI 会话号和 FAQ 上传缺少统一长度/体积上限 | 已修复：控制器增加长度约束，会话号限制 64，上传限制 2 MB |
| AUD-17 | 内容安全 | “跟进”接口绕过了建单、普通消息和 AI 对话已有的内容校验 | 已修复：跟进写入前执行相同内容校验 |
| AUD-18 | 异步容量 | Spring MVC 使用默认 `SimpleAsyncTaskExecutor`，并发 SSE 下可能无限创建线程 | 已修复：配置有界 MVC 异步线程池、队列和 75 秒请求超时 |
| AUD-19 | 前端角色与跳转 | AGENT/ADMIN 在 AI 页面仍看到仅 USER 可用的创建工单按钮；登录重定向未约束为站内路径 | 已修复：按钮按角色显示；登录仅接受单斜杠开头的站内重定向 |

## 4. 真实环境验收风险

- 真实 DashScope 模型是否稳定选择正确的列表/精确查询工具。
- MySQL 开发库是否已经执行最新全量迁移，且历史数据没有无效分组或分类引用。
- 三角色浏览器流程、并发接单、SLA 扫描、CSV 中文和 Excel 打开效果。
- 模型不可用、Token 失效、网络中断时 SSE 页面和会话历史的最终表现。

上述项目是需要真实 MySQL、浏览器或 DashScope 的验收项，不代表已知代码缺陷仍未修复。发现新问题时继续在本文件追加编号、复现步骤、根因、修复和验证证据。
